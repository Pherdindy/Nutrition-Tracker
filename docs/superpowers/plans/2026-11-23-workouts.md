# Workouts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Written by and
> for the agent that executes it in the same session; the user waived reading it. The
> tests named here are written first, and the code is in the tasks' commits rather than
> repeated here.

**Goal:** Log workouts whose calories the AI works out, next to one-tap activity choices,
without counting anything twice.

**Architecture:** A pure module (`www/workouts.js`) decides everything about a workout and
a day's total. Workouts are rows of their own table and use the food sync and estimate
queue, which are first made to work for any *spec*. The proxy gains a `workout` feature.

**Tech Stack:** Vanilla JS (UMD modules), Supabase (PostgREST, RLS), Deno Edge Function,
Node `--test`.

**Spec:** `docs/superpowers/specs/2026-11-23-workouts-design.md`

---

### Task 1: Sync and queue for any spec (no behaviour change)

**Files:** Modify `www/app.js`. Tests: existing ones stay as they are and pass.

- [ ] A *spec* is `{ table, keyColumn, onConflict?, known, keyOf, toRow, fromRow,
  signature, load(), save(list), show(), answerFields?, askedOf?, againOf? }`. `SYNCED =
  { food_entries, days, workouts }`; those with `answerFields` can be estimated.
- [ ] `takeOver(uid, table, key)`, `changedElsewhere`/`follow`, `outbox.agrees`,
  `applyEstimate` and `saveEstimates(spec, entries, answered, was)` use the spec.
- [ ] The estimate queue holds `{ kind, id }`; a kind is `{ spec, needs(e), without(e),
  ask(e, asked), applied(e, answer, noCredit) }`. `FOOD` is the first kind. 402 drains
  every kind.
- [ ] `npm test`: all pass. Commit.
