# AI Proxy + Metering + Plans (Spec B)

**Date:** 2026-07-30
**Status:** Approved
**Series:** Spec B of the SaaS-launch sequence: **A — Accounts** (shipped 2026-07-29, live-verified) → **B — AI proxy + metering** (this doc) → **C — Google Play Billing**.

## Problem

The shipped app is BYOK: provider API keys live in the client's localStorage and
every AI call goes browser → provider. That blocks a paid product three ways:
keys shipped in an APK are extractable, usage can't be metered per user, and
model choice is frozen into each installed version. Spec B moves every AI call
behind a server the owner controls, meters real provider cost per user, and
turns model quality into the paid ladder.

## Decisions (locked in brainstorming, 2026-07-30)

1. **Everything is dual-model.** Every AI feature runs a pair of models (A + B)
   in parallel. Tiers do NOT gate features — they buy **model quality**: free
   runs a cheap pair (Haiku-class + mini-class); higher tiers run progressively
   stronger pairs (Opus/Fable-class + GPT-5-class at $10). The tier→pair
   mapping is server config, per feature.
2. **Pricing** (from the 2026-07-07 umbrella): free = **$1.00 of real provider
   cost, lifetime**; paid = **$3 / $5 / $10 per month** with allowances of
   roughly $1.20 / $2.25 / $5.00 provider cost (~60% margin, tunable in
   config).
3. **Exhaustion = AI paywall, app stays useful.** AI buttons open the upgrade
   prompt; manual logging, day cards, targets, and history work forever.
4. **Proxy shape: server merges each pair.** One Edge Function, four features
   (`estimate`, `photo`, `assess-round1`, `assess-round2`); each invocation
   runs exactly one model pair in parallel and returns one merged result
   (estimates) or both analyses (assessment rounds). The client keeps its
   existing R1→R2 handoff; the server owns prompts, model choice, and merge
   rules.
5. **Ledger-only accounting.** Quota checks sum the append-only `ai_usage`
   ledger (indexed, sub-ms at this scale). No cached balance row to drift.
6. **Owner account** (`plan = 'owner'`) bypasses quota but still logs usage.
7. **Paid windows reset on calendar month (UTC)** until spec C brings billing
   anchors; `entitlements.period_start` exists so C swaps that in without a
   schema change.
8. **Credit bar shows percent**, never raw dollars or action counts (umbrella
   decision). Model names never reach the client.

## Architecture

```
app ──callAi(feature, payload)──► Edge Function ai-proxy
                                    │ 1. validate JWT
                                    │ 2. load ai_config + entitlement (upsert free row if new)
                                    │ 3. kill-switch check (config.enabled)
                                    │ 4. rate-limit check (~10 proxy calls/min/user)
                                    │ 5. quota pre-check (SUM ledger vs allowance)
                                    │ 6. model pair by tier + feature
                                    ├─► Model A ┐ parallel
                                    ├─► Model B ┘
                                    │ 7. merge (feature-specific)
                                    │ 8. insert ai_usage row (real cost, service role)
                                    └─► one result to the client
```

Provider keys (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`) are Supabase Edge
Function secrets — never in git, never in the client. The provider dashboards'
hard budget alerts remain the outer fuse; `ai_config.enabled = false` is the
inner kill switch (proxy returns a friendly 503).

## Data model

```sql
-- Append-only ground truth. One row per proxy invocation (= one user action).
create table ai_usage (
  id           bigint generated by default as identity primary key,
  user_id      uuid not null references auth.users(id),
  feature      text not null,          -- estimate | photo | assess-round1 | assess-round2
  model_a      text not null,
  model_b      text,                   -- null when the pair degraded to single-model
  tokens_in_a  int, tokens_out_a int,
  tokens_in_b  int, tokens_out_b int,
  cost_usd     numeric(8,6) not null,  -- summed real cost of both calls
  created_at   timestamptz default now()
);
create index on ai_usage (user_id, created_at);
-- RLS: users SELECT their own rows; INSERT via service role only.

create table entitlements (
  user_id      uuid primary key references auth.users(id),
  plan         text not null default 'free',   -- free | t3 | t5 | t10 | owner
  status       text not null default 'active',
  period_start date,                            -- paid monthly anchor (spec C manages)
  created_at   timestamptz default now()
);
-- Default free row upserted by the proxy on first call.
-- RLS: users SELECT their own row; writes via service role only.

-- Single-row config: every commercial dial, editable without code changes.
-- { enabled, rate_per_min,
--   plans: { free: { allowance_usd: 1.00, lifetime: true,
--                    models: { estimate: [A,B], photo: [A,B], assess: [A,B] } },
--            t3:  { allowance_usd: 1.20, models: {...} },
--            t5:  { allowance_usd: 2.25, models: {...} },
--            t10: { allowance_usd: 5.00, models: {...} } },
--   prices: { "<model_id>": { in_per_mtok, out_per_mtok } },
--   merge:  { widen_threshold: 0.4 } }
create table ai_config ( id int primary key check (id = 1), value jsonb not null );
-- Server-private: no client grants at all (model names stay hidden).
```

**Initial model ladder** (config seed; each pair = one Anthropic + one OpenAI
model for genuinely independent perspectives; exact OpenAI ids taken from the
app's current model constants at implementation time):

| Plan | Pair class | Anthropic side |
|---|---|---|
| free | cheapest vision-capable pair | `claude-haiku-4-5` |
| t3 | mid pair | `claude-sonnet-5` |
| t5 | mid/strong pair | `claude-sonnet-5` (assess: `claude-opus-5`) |
| t10 | strongest pair | `claude-opus-5` |

Both rounds of an assessment use the plan's `assess` pair.

**Rate limit** = count of the user's `ai_usage` rows in the trailing 60
seconds vs `config.rate_per_min` (seed: 10) — no separate counter table.

**Cost** = provider usage objects (token counts) × the config price table.
Real cost is ground truth — never client-side estimates.

**Quota:** free sums the user's ledger all-time (`lifetime: true`); paid sums
since the start of the current calendar month (UTC). `plan = 'owner'` skips
the check.

**Credit bar data:** a `security definer` RPC `ai_usage_summary()` returns
`{ pct_used, plan, exhausted }` for `auth.uid()` — percent only.

## Edge Function

**Layout:**
- `supabase/functions/ai-proxy/index.ts` — HTTP handling, provider adapters
  (OpenAI chat completions + Anthropic messages), usage extraction.
- `supabase/functions/_shared/metering.mjs` — **pure ESM, dependency-free**:
  quota math, cost calculation, merge/widen rule, rate-limit window logic.
  Imported by the Deno function AND by the repo's `node --test` suite — one
  logic, two runtimes, no duplication.

**Features and response shapes** (mirror what the client already stores):
- `estimate` — payload: food name, qty, unit. Both models return range
  estimates; server merges: `cal_low`/`pro_low` = average of the two lows,
  highs likewise; if the models' calorie midpoints diverge by more than
  `merge.widen_threshold` (40%), widen the merged range to cover both
  midpoints. Returns one `{ cal_low, cal_high, pro_low, pro_high, macros,
  ai_thought_process }`; the thought process carries both models' reasoning.
  Macros are averaged per field.
- `photo` — same as `estimate` plus the base64 data URL the existing
  `photo.js` flow produces; size guard ~5 MB; vision-capable pair per tier.
- `assess-round1` — payload: the compiled assessment data package. Returns
  both analyses labeled A/B (anonymization now enforced server-side).
- `assess-round2` — payload: the R1 analyses. Returns both reconcile verdicts
  labeled A/B. The "don't compromise — cite specific foods" instruction
  becomes a server-owned system prompt.

**Prompts live server-side for all four features.** Prompt tweaks are Edge
Function redeploys (seconds via the Supabase MCP `deploy_edge_function`), not
app releases.

**Error contract:**

| Status | Meaning | Client behavior |
|---|---|---|
| 401 | no/invalid JWT | send to sign-in gate |
| 402 | quota exhausted | paywall modal |
| 429 | rate limited | "one moment" toast |
| 502 | both models failed | existing failure/retry state; nothing charged |
| 503 | kill switch off / unpriced model in config | friendly outage message |

**Partial failure:** one model fails → return the survivor's result,
`model_b = null` in the ledger, charge only actual usage. Both fail → 502 —
and (amended by Task 5 review) a ledger row IS written: at the real cost of
any usage the failures carried (truncated output is provider-billed and must
be metered), or $0 otherwise, so failures count toward the rate limit and
can't form a free unmetered retry loop.

**Metering order:** ledger row written AFTER provider responses (real token
counts). Insert failure → one retry → loud function log. Worst case loses
cents of billing, never the user's result.

## Client changes (`www/`)

**Removed:** both provider adapters (app.js ~730–890 and ~1790–1830),
primary/secondary model settings UI, BYOK key fields, all `nt_key_*` handling
— plus a one-time migration that **deletes stored provider keys from
localStorage** (no orphaned secrets on devices).

**Added:**
- `callAi(feature, payload)` — wraps `sb.functions.invoke('ai-proxy', …)`,
  maps the error contract above. The `_estimateQueue`, `estimate_status`
  retry flow, assessment R1→R2 handoff, and all rendering stay untouched.
- **Credit bar** in the Targets tab settings area (where key fields were):
  "AI usage: 63% used" + plan name, fed by `ai_usage_summary()`, refreshed
  after each AI call. At 100% on free: bar red, AI buttons open the paywall.
- **Paywall modal:** "You've used your free AI credit" + three tier cards
  ($3/$5/$10 — bigger allowance, smarter models). CTAs disabled with
  **"Paid plans coming soon"** until spec C ships. Manual logging never gates.

## Edge cases

- **Concurrent calls** can jointly overshoot an allowance by a call or two —
  bounded by the rate limit, worth pennies; accepted (no reservation system).
- **Exhaustion mid-assessment:** R1 passes, R2 hits 402 → paywall; the
  partial round is discarded, no half-assessments stored.
- **Unpriced model in config** (edit mistake): refuse with 503 rather than
  run unpriced — a config error can't silently give away usage.
- **Offline:** proxy unreachable → the existing pending/failed retry
  machinery; no new offline logic.
- Period windows are UTC; `lifetime: true` skips the window filter.

## Testing

- **Unit (Node, existing suite):** `_shared/metering.mjs` — quota math
  (lifetime vs monthly window, boundary at exactly 100%), cost calc from both
  providers' usage-object shapes, merge/widen rule (agreeing pair, >40%
  divergence, single-model degradation), rate-limit window edges. Suite
  target: 90+ tests.
- **Live (MCP + emulator):** deploy → seed `ai_config` + owner entitlement →
  emulator smoke of all four features as the owner → flip a test account to a
  0.001-allowance plan to walk the real exhaustion path (credit bar red, 402,
  paywall, manual logging fine) — the same two-account CDP method that
  verified Spec A.

## Rollout (two independent steps)

1. **Server first:** tables + RPC + function + config are purely additive —
   the shipped BYOK app keeps working untouched.
2. **Client swap:** one release replaces provider calls with `callAi`,
   removes key UI, deletes local keys.

No migration window where users are broken.

## Out of scope

Payment processing (spec C), streaming responses, web deploy, charts (next in
queue), per-user model preferences.
